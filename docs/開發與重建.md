# 開發與重建

## 建立工作環境

1. Clone 此儲存庫；建議保留一份獨立的測試分支。
2. Python 3.10+ 用於還原資產與製作工具；Rojo 用於把原始碼組成 place；官方 Luau CLI 用於純邏輯測試。直接開啟已交付 `.rbxl` 只需要 Roblox Studio。
3. 在儲存庫根目錄執行 `python3 tools/restore_assets.py --download`。也可用 `--archive` 指向已下載的 v9 ZIP。
4. 執行 `python3 game/tools/build_place.py`，在 Studio 開啟生成的 `game/DragonAwakening-Atelier-v9.rbxl`。

還原工具會檢查整個來源 ZIP 和三個固定目標檔的 SHA-256，跳過內容相同的檔案；若目標已有不同內容則停止，需備份後明確使用 `--force`。它不會把 ZIP 中的腳本覆蓋到你的工作目錄。

## 常改的位置

| 修改內容 | 主要入口 |
|---|---|
| 物品名稱、裝備能力、套裝、商店 | `game/src/ReplicatedStorage/DragonShared/Catalog.luau` |
| 島嶼、地標、生成資料 | `game/src/ReplicatedStorage/DragonShared/WorldData.luau` |
| 真正掉落權重與伺服器設定 | `game/src/ServerScriptService/DragonServer/Settings.luau` |
| 經濟、裝備、獎勵與升級 | `game/src/ServerScriptService/DragonServer/Domain.luau` |
| 客戶端 GUI | `game/src/StarterGui/DragonUI/Controller.client.luau` 與共用 `UI/` |
| 飛行判定 | `TravelService.luau`、`TravelRules.luau` |
| 飛行顯示與鏡頭 | 共用 `UI/RidePresentation.luau`、`RideMotion.luau` |
| 怪物與裝備外觀 | `game/art/visual-recipes.json`、`VisualChunks/` 與烘焙模型 |

掉落機率有伺服器實際權重與顯示資訊的一致性檢查，修改時要同步 `Settings`、`LootInfo` 和掉落文件。JSON 為製作／參照資料，執行中的 Luau 模組不會因手改 JSON 自動更新。

## 造型、烘焙與預覽

`game/tools/refine_models.py` 每次從 `art/base-v8-recipes.json` 重建 v9 配方及其輸出；不要把臨時手改的輸出當唯一來源。`BakeModels.luau`、`BakeScenery.luau` 是 Studio 內的製作工具；`render_catalog.py` 需要 Blender，產出另行渲染的預覽圖。

僅修改配方不會改變已存好的 `BakedArt.rbxmx`。必須依工具內容在 Studio 重新烘焙、匯出模型並更新場景，再 build。一般玩家不必啟用動態 Mesh API。

使用 Rojo live sync 前先確認資料來源：完整場景和烘焙模型由 `.rbxmx` 提供；Studio 中的未匯出修改可能在同步時被磁碟版本取代。先另存測試副本，避免直接在唯一的手動編輯場景上試同步。不要同時把不同版本模型混在一個專案。

## 驗證

```sh
python3 game/tests/run_checks.py
```

此命令執行純規則與移動服務的引擎替身測試，不會啟動 Studio，也不能證明多人或 DataStore 已通過。遊玩驗收流程見 [測試與驗收](../game/docs/測試與驗收.md) 及 [v9 驗收](../game/docs/v9細化與驗收.md)。

發布新版本時，同步程式、劇本狀態、驗收紀錄、完整 ZIP、SHA-256 和下載索引。`game/SHA256SUMS.txt` 是原 v9 交付內容的歷史校驗清單；新增的儲存庫文件不在其中。Releases 的下載檔校驗請以 `archive/SHA256SUMS.txt` 為準。
